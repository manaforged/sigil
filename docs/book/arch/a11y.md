# Accessibility

Every kernel node carries `A11yProps` (role, name, state signals,
live region). `sigil-a11y` is the only crate that builds an
`accesskit::TreeUpdate`.

Widgets set roles and names on the kernel side. The bridge reads
them. There is no second a11y tree that widgets must keep in sync.

## When it updates

`launch` remaps AccessKit on paint from `tree()` plus a bounds
lookup on `LayoutEngine`. It peeks live state (`checked`, name
signals) at that moment. There is no separate a11y dirty drain or
`A11yObserver`.

AT actions (focus, click) drain in the layout phase against this
frame's boxes, so a Focus action's signal write is visible in the
same paint.

## Headless

Tests call `sigil_a11y::tree(&cx, root, bounds)` and assert roles
and names. No window. See `crates/a11y/tests/`.

## What this is not

crates.io GPUI 0.2.2 does not ship AccessKit. Zed's tree does, and
the product still has platform gaps. Sigil's path is: kernel
semantics → one bridge → AccessKit, on every painted frame that
needs a remap.
