# DR-050 — G10 Accessibility Substrate

**Status:** Proposed
**Date:** 2026-05-18
**Covers:** G10 keystone — AccessKit `TreeUpdate` bridge wiring from the
composed kernel tree, the per-widget `Role + Name` discipline that gates
Wave 5 widget dispatch, the `assert_a11y_tree!` snapshot test seam, the
keyboard-navigation flat-ring contract (Tab / Shift+Tab + `FocusScope`
traps), the WCAG 2.2 AA conformance target, the live-region
announcement timing rule (Effect phase drain, never Paint).
**Depends on:** DR-008 (a11y is a Phase-1 concern, AccessKit is the
abstraction, every node carries semantic identity from commit one),
DR-040 (sigil thesis — own the substrate, mirror what works), DR-045
(`Entity<T>` / `Context` — the write seam state-change announcements
hang off), DR-046 (`FocusHandle` + focus path — the input side of the
a11y `Focused` projection), DR-047 (DrawPhase — announcements drain in
Effect, never Paint).
**Unlocks:** Wave 5 widget catalogue (each widget ships with a Role +
Name + state-signal contract baked in; no a11y backfill debt), the
a11y-reviewer agent gate (auto-checks every widget against WCAG 2.2 AA),
the cross-platform a11y CI surface that closes the loop opened by
DR-008 (NVDA / VoiceOver / Orca smoke tests).

## Context

DR-008 (April 2026) committed sigil to a Phase-1 accessibility shape:
AccessKit is the abstraction, every `NodeId` is also the
`accesskit::NodeId`, every node carries semantic identity (`Role`,
`AccessibleName`, actions, focusable, shortcut) from the first commit.
The trait-level contract landed in `crates/hal/src/a11y.rs`
(`A11yBridge::publish` + `take_action`); the data shape landed in
`crates/kernel/src/semantics.rs` (`A11yProps`); the focus update channel
landed in `crates/events/src/focus.rs::FocusManager::a11y_focus_update`.

What that leaves un-locked, and what G10 closes:

1. **Bridge crate location and shape.** DR-008 anticipated a `ui-a11y`
   crate that derives an incremental `TreeUpdate` stream from node
   mutations. That crate does not exist. The HAL trait stops at the
   wire; no consumer wires `A11yProps` → `accesskit::Node` ingestion
   yet. Wave 5 cannot ship widgets without an answer to "what does
   `cargo test --tests a11y` actually do?"
2. **Per-widget contract.** Every existing widget already calls
   `.role(Role::…)` and `.aria_label(…)` (verified across
   `button.rs`, `checkbox.rs`, `text_field/render.rs`). The contract
   is *de facto* in place; what is missing is the rule that gates
   dispatch — "you may not land a widget without both" — and the test
   that mechanically enforces it for every catalogue widget.
3. **a11y test seam.** Visual goldens (DR-041 / pixel diff) catch
   rendering regressions but not semantic regressions. A widget that
   renders a checked checkbox visually while reporting
   `accesskit::Toggled::Off` to a screen reader passes pixel diff and
   fails the user. G10 locks an a11y-tree snapshot seam — cheap, fast,
   semantically precise — sized to run on every catalogue widget.
4. **Focus contract for entities.** DR-046 introduced `FocusHandle` and
   the focus path (owner-ancestry walk). `FocusManager`
   (`crates/events/src/focus.rs`) focuses node-IDs. The bridge from
   *node focus* (the events-crate truth) to *entity focus*
   (DR-046's truth) is the seam G10 must lock — the AccessKit
   `Focused` projection reads node focus, the action dispatcher reads
   entity focus, and the two cannot disagree.
5. **Keyboard navigation walk order.** `FocusManager` already builds a
   tab ring from a depth-first walk of the kernel tree
   (`focus.rs::build_ring`). What is not locked is whether that ring
   honours `tab_index`, how `FocusScope` (modal / popup) constrains
   the walk, and what "first focusable on window open" resolves to.
6. **Live-region announcement timing.** State changes that should
   announce (error appeared, button pressed, value changed) need a
   single drain point. DR-047 locked Effect → Layout → Paint → Idle
   → Effect. Announcements emitted mid-Paint produce reordered AT
   output and can race the screen reader's polling loop on three
   adapter platforms. G10 picks one drain seam — end of Effect, before
   Layout — and writes it down.
7. **WCAG conformance target.** "Accessible" without a published bar
   is a marketing claim, not a verification target. DR-008 deferred
   this. G10 names the target (WCAG 2.2 AA), enumerates the load-
   bearing criteria, and points each criterion at the crate that
   implements it.

### Reading the existing repo

Files this DR builds on, by path:

- `crates/kernel/src/semantics.rs` — `A11yProps` shape. Fields cover
  `role`, `name` (Static / Derived / LabelledBy), `description`,
  `actions`, `focusable`, `tab_index`, `keyboard_shortcut`,
  `hit_test_enabled`, `checked` (Signal), `value_now` + min + max
  (Signal), `text_value` (Signal), `placeholder`, `aria_owns`,
  `aria_labelled_by`. The data is sufficient; G10 reads it.
- `crates/kernel/src/builder.rs` lines 43–158 — the `NodeBuilder::role`
  + `aria_label` + `aria_label_signal` + `labelled_by` + `focusable`
  + `tab_index` + `keyboard_shortcut` + `aria_checked_signal` +
  `aria_value_signal` + `aria_text_value_signal` + `aria_placeholder`
  authoring surface. Widgets already use this surface (see
  `widgets/button.rs:152-154`, `widgets/checkbox.rs`,
  `widgets/text_field/render.rs:32-36`). G10 does not reshape the
  surface; G10 locks the dispatch rule on top of it.
- `crates/hal/src/a11y.rs` — `A11yBridge` trait with associated
  `Update` + `Action` + `NodeId` types. Publish + drain-action
  surface. This is the wire. G10 picks an in-crate type for the
  associated types (`accesskit::TreeUpdate`, `accesskit::ActionRequest`)
  and writes the bridge.
- `crates/events/src/focus.rs` lines 1–100 — `FocusManager` (node-keyed
  focus, lazy tab ring, `a11y_focus_update` that emits an AccessKit
  focus-only `TreeUpdate`). G10 extends this with `FocusScope` traps
  and reconciles with `FocusHandle` from DR-046.
- `crates/kernel/src/id.rs` — `NodeId::to_accesskit` already maps the
  kernel id to `accesskit::NodeId` (the unification DR-008 promised).
- `crates/kernel/src/lib.rs` line 35 — `pub use accesskit::{Action,
  Role};` confirms AccessKit is the canonical role enum throughout
  kernel. G10 does not add a parallel `sigil::Role`.

### What does not exist

- **No `crates/a11y/` crate.** No `build_a11y_tree(root: &Cx) ->
  accesskit::TreeUpdate` function. The data is on every node; nothing
  reads it.
- **No `assert_a11y_tree!` macro.** No `tests/snapshots/a11y/`
  directory. No mechanism to assert a widget's Role / Name / State.
- **No `FocusScope`.** Modals, popups, and dropdowns have no way to
  trap Tab inside their subtree; today Tab from inside an open
  dropdown walks past the dropdown root to whatever comes next in DOM
  order.
- **No `tab_index` honoring.** `FocusManager::build_ring` walks DOM
  order and ignores `A11yProps::tab_index`. Two widgets that need
  explicit ordering (form field sequence) cannot express it.
- **No live-region drain.** Nothing computes "what state changed this
  frame that the AT should hear?" — there is no AccessKit `live`
  annotation on any node and no Effect-phase emission of `live`
  notifications.

The mistake to avoid is plumbing AccessKit one widget at a time. That
is the retrofit DR-008 warned against: every widget reaches into the
adapter directly, the bridge becomes one widget's bug surface, and the
"build a tree once per frame" invariant rots within a quarter.

G10 owns the indirection. Every widget keeps writing
`.role(...).aria_label(...).aria_checked_signal(...)`; the new
`sigil-a11y` crate is the one consumer of those fields, and it produces
exactly one `TreeUpdate` per frame.

## Decision

Ten decisions, frozen for the W4.G10-impl implementer.

### 1. AccessKit is the abstraction; the bridge crate is `sigil-a11y`

The new crate `crates/a11y/` (package name `sigil-a11y`, version pin
`accesskit = "0.24"` — matching the workspace pin already in
`Cargo.toml`) owns the AccessKit wiring. It depends on:

- `sigil-kernel` (read `A11yProps`, `Node`, `NodeId`, `Cx`)
- `sigil-reactive` (subscribe to signals on `A11yProps::checked`,
  `value_now`, `text_value`, `name::Derived`)
- `sigil-hal` (implement `A11yBridge` over `accesskit::Adapter`)
- `accesskit` (workspace dep)

The crate does **not** depend on `sigil` (the widget surface) or
`sigil-events`. Events-crate consumes a11y (calls `set_focus`,
publishes focus-only `TreeUpdate`s); the a11y crate does not consume
events.

Why a new crate, not a module on `sigil-kernel`:

- Kernel owns the data model. Wiring AccessKit is policy that depends
  on a published `accesskit` SemVer; pinning kernel to a specific
  AccessKit version contaminates every consumer of kernel.
- The bridge is a future swap point (per DR-008 kill-criteria: "if a
  better cross-platform a11y library appears, we replace the platform
  adapter while keeping the semantic tree shape"). A separate crate
  lets that swap land without touching kernel.
- `crates/a11y/` is the canonical the author path-nested layout
  (per `feedback_crate_naming`) for a leaf crate; `sigil-a11y` is the
  package name.

### 2. The a11y tree mirrors the kernel node tree 1:1

For every kernel `NodeId` that is not a `Fragment`, the a11y crate
emits one `accesskit::Node`. Fragments produce no a11y node — their
children appear as direct children of the fragment's parent in the
a11y tree, matching the layout-side fragment semantics
(`crates/kernel/src/node.rs:130-156`).

The mapping rule per node (locked):

| Kernel field                              | AccessKit projection                                |
| ----------------------------------------- | --------------------------------------------------- |
| `NodeId` (via `NodeId::to_accesskit`)     | `accesskit::Node::node_id`                          |
| `A11yProps::role`                         | `accesskit::Node::role` (direct, same type)         |
| `A11yProps::name::Static(s)`              | `Node::set_name(s)`                                 |
| `A11yProps::name::Derived(sig)`           | `Node::set_name(sig.get())`, observer subscribed    |
| `A11yProps::name::LabelledBy(id)`         | `Node::set_labelled_by([id.to_accesskit()])`        |
| `A11yProps::description`                  | `Node::set_description(...)` (Static / Derived)     |
| `A11yProps::actions`                      | `Node::set_supported_actions(actions)`              |
| `A11yProps::focusable`                    | contributes to focus ring; no AccessKit flag        |
| `A11yProps::tab_index`                    | drives ring order (Decision 6)                      |
| `A11yProps::keyboard_shortcut`            | `Node::set_keyboard_shortcut(formatted)`            |
| `A11yProps::checked = Some(sig)`          | `Node::set_toggled(Toggled::from(sig.get()))`       |
| `A11yProps::value_now / min / max`        | `Node::set_numeric_value(...)`, min/max             |
| `A11yProps::text_value = Some(sig)`       | `Node::set_value(sig.get())`                        |
| `A11yProps::placeholder`                  | `Node::set_placeholder(s)`                          |
| `A11yProps::aria_owns`                    | parent/child override via `Node::set_children` ext  |
| `A11yProps::hit_test_enabled = false`     | `Node::set_hidden(true)` on the a11y projection     |
| `LayoutResult` bounds (read from kernel)  | `Node::set_bounds(Rect { … })`                      |
| `FocusManager::focus() == Some(id)`       | `TreeUpdate::focus = id.to_accesskit()`             |

The mapping table is implemented as one function:

```text
crates/a11y/src/mapping.rs
fn project_node(cx: &Cx, id: NodeId) -> accesskit::Node
```

The table is centralized in `mapping.rs` and does not live in widget
code. Widgets author `A11yProps`; the table reads it; no widget reaches
into AccessKit types directly. This is the seam DR-008 named as
non-negotiable.

### 3. Every widget MUST set `Role` and `Name` — compile-time gate

`NodeBuilder::role` and `NodeBuilder::aria_label` /
`aria_label_signal` / `labelled_by` already exist. The gate G10 adds is
a debug-assert at `Cx::build` time:

- Every `Container` node whose `A11yProps::role != Role::GenericContainer`
  must also have `A11yProps::name != AccessibleName::None`. The assert
  fires in debug builds at the moment a built node is attached to the
  arena; release builds skip the check (consistent with DR-005 / DR-046
  assertion policy).
- `Role::GenericContainer` is the explicit opt-out for layout-only
  containers (a Card row that wraps two buttons doesn't have a Name;
  the buttons do). Authoring discipline: if a widget *has* a role, it
  also has a name.
- The assert message names the violation: `"widget node with role
  {role:?} has no AccessibleName — every named role must have a Name
  (DR-050 §3); use Role::GenericContainer for layout-only wrappers"`.

Widget authoring contract (the rule Wave 5 dispatches reference):

1. Every widget's root `container()`/`fragment()` call sets `.role(…)`
   to a non-`GenericContainer` role.
2. Every named-role node sets `.aria_label(…)` or
   `.aria_label_signal(…)` or `.labelled_by(node_id)`.
3. Every state-bearing widget sets the corresponding signal hook:
   `.aria_checked_signal(...)` for checkboxes, `.aria_value_signal(...)`
   for sliders, `.aria_text_value_signal(...)` for text inputs.

This is *de facto* the existing pattern in `button.rs`, `checkbox.rs`,
`text_field/render.rs`. G10 makes the pattern enforced rather than
followed.

### 4. State signals propagate via existing observer fan-out

When the `Signal<bool>` backing a checkbox's `A11yProps::checked`
changes, the AccessKit tree must update before the next adapter poll.
G10 hooks this into the existing reactive substrate; no new
observer infrastructure:

- The a11y crate registers one observer per `Signal`-bearing
  `A11yProps` field at node-attach time
  (`A11yProps::checked`, `value_now`, `text_value`,
  `name::Derived`, `description::Derived`). The observer's effect is
  one statement: mark this `NodeId` dirty in
  `A11yDirtySet: AHashSet<NodeId>`.
- At end of Effect (per Decision 8), `A11yBridge::publish` is called
  with a `TreeUpdate` containing only the dirty nodes plus the focus
  delta from `FocusManager`. Clean nodes are not re-published.
- Observer lifetime tracks the node's reactive owner (DR-005 cascade).
  Disposing a node disposes its a11y observers automatically — no
  manual deregistration in widget code.

The `A11yDirtySet` is the only new piece of state. It lives on
`RuntimeState` (alongside the DR-046 focus arena and the DR-047
phase machine), not on the a11y crate's bridge struct, because the
observer-fan-out path already touches `RuntimeState` and threading the
dirty set through the bridge would require a second mutable borrow.

### 5. Focus contract — node focus is the AccessKit truth; entity focus is the dispatcher truth; the bridge is `FocusHandle`'s node-extension

DR-046 introduced `FocusHandle` (entity-scoped) and named the bridge:
"the events-crate calls `Runtime::set_focus(focus_key)` when the
node-focus changes" via a "node-side `FocusHandle` extension." G10
locks that extension's shape:

- Kernel grows one extension type: `FocusHandleNodeExt { handle:
  FocusHandle }`. Attached at widget-build time by widgets that
  participate in entity-focus (every focusable widget). Not stored on
  `A11yProps` — extension storage, accessed via
  `node.get_extension::<FocusHandleNodeExt>()`.
- `FocusManager::set_focus(cx, node_id)` reads the extension on the
  newly-focused node; if present, calls `cx.with_runtime(|rt|
  rt.set_focus(handle.key))` to mirror node-focus to entity-focus.
- AccessKit `TreeUpdate::focus` reads `FocusManager::focus()`. The
  events crate is the source of truth for the AccessKit projection.
- When the AT dispatches a `Focus` `ActionRequest` (incoming via
  `A11yBridge::take_action`), the a11y crate calls
  `FocusManager::set_focus(cx, action.target)`. The events crate then
  fires `on_focus_in` / `on_focus_out` (existing path) and mirrors to
  entity focus. One drain point, one direction per update.

This wiring resolves the apparent dual-truth problem: node focus and
entity focus are always equal because they share one set-path. The
extension bridge is the only place the bridge happens; widgets do not
manage it (they call `.focusable(true)` and the framework attaches the
extension when needed).

### 6. Keyboard navigation — flat ring in DOM order, honors `tab_index`, traps inside `FocusScope`

Tab / Shift+Tab walk a flat ring computed by
`FocusManager::build_ring`. G10 changes the build rule:

1. Walk the kernel tree depth-first in document order
   (already happens).
2. For each node where `A11yProps::focusable == true` and
   `A11yProps::hit_test_enabled == true`, push to a candidate vec.
3. **Stable-sort the candidate vec by `tab_index`:** nodes with
   `tab_index = None` keep DOM order; nodes with `tab_index = Some(n)`
   sort with positive `n` first (ascending), then `None`, then
   negative `n` (descending — negative excludes from default flow,
   matching HTML semantics). Stable sort preserves DOM order within
   each tab-index bucket.
4. Inside an active `FocusScope`, the ring is restricted to descendants
   of the scope root.

`FocusScope` is a new kernel-level extension and one builder method:

- `NodeBuilder::focus_scope(FocusScopeKind)` — attaches a
  `FocusScopeExt { kind: FocusScopeKind, restore_to: Option<NodeId> }`
  extension. Kinds: `Modal` (traps Tab inside, restores focus on
  scope drop), `Popup` (traps Tab, click-outside escapes), `Inert`
  (descendants get `hidden = true` in the a11y tree).
- `FocusManager` maintains a stack of active scopes
  (`scope_stack: SmallVec<[NodeId; 2]>`). `focus_next` / `focus_prev`
  read the stack top to constrain the ring.
- On scope drop (the scope-attached node is removed from the tree),
  `FocusManager` restores focus to `restore_to` and pops the stack.

Why DOM order, not painted Z-order: AT users expect tab order to
match reading order, not visual stacking. Reading order is DOM order
in every spec that covers this (WCAG 2.4.3 Focus Order). Z-order
diverges from DOM for valid reasons (popovers, overlays) and those are
exactly what `FocusScope::Popup` covers separately.

Why explicit `tab_index` sorting, not pure DOM: form-field flow needs
explicit reordering when a label sits after its input in DOM, or when
a primary action sits at the top of the visual hierarchy but should
receive focus last. HTML solved this with `tabindex`; we mirror.

### 7. a11y tree snapshot test seam — `assert_a11y_tree!` macro + indented-text format

The test seam is a declarative macro that:

1. Mounts the widget under test in a headless `Cx` (via the existing
   `frame_driver` harness shape — see
   `crates/sigil/tests/frame_driver.rs` analogue).
2. Drives one Layout pass to populate bounds.
3. Calls `sigil_a11y::build_a11y_tree(&cx)` to produce a
   `TreeUpdate`.
4. Formats the resulting tree as indented text (Role + Name + State
   per node, two-space indent per depth level).
5. Compares against a snapshot file at
   `tests/snapshots/a11y/<widget_name>.txt` using the existing
   `insta`-style review flow (locked at workspace level in the
   visual-gate pattern from FE1).

Snapshot format (locked, sample):

```text
window[Role=Window, Name="App"]
  container[Role=GenericContainer]
    button[Role=Button, Name="Save", Focused=false]
    button[Role=Button, Name="Cancel", Focused=true]
    text_field[Role=TextInput, Name="Email", Value="", Placeholder="email@example.com"]
    checkbox[Role=CheckBox, Name="Remember me", Toggled=Off]
```

Why indented text, not JSON:

- Snapshot diffs in code review read at a glance; nested JSON does
  not. The widget-tree shape is the load-bearing comparison; the
  text format makes structural deltas visible without parsing.
- The existing pixel-diff golden harness (`tests/snapshots/...`)
  already uses an indented-text format for layout asserts; consistency
  with that harness reduces the test-author cognitive overhead.
- JSON snapshots regenerate noisily when AccessKit adds an optional
  field (every snapshot bumps). The indented format includes only the
  fields the test asserts on; new AccessKit fields don't flake
  existing snapshots.

The macro lives in `crates/a11y/src/snapshot.rs`; tests in any crate
can pull it via `sigil_a11y::testing::assert_a11y_tree`.

### 8. Live-region announcement timing — drain at end of Effect, before Layout

State changes that should announce (form-field error message
appeared, value-changed on a slider crossing a threshold, button
pressed) need exactly one drain point. G10 picks:

- **End of Effect phase, before Layout** (per DR-047's phase order:
  Effect → Layout → Paint → Idle).
- The drain calls `A11yBridge::publish(tree_update)` exactly once per
  frame. The `tree_update` contains: every dirty node from
  `A11yDirtySet`, the current focus delta, and the live-region
  notifications collected during this Effect's observer fan-out.
- Live-region annotation on a node is set by widgets via
  `NodeBuilder::aria_live(Live::Polite | Live::Assertive)` (new
  builder method, writes `A11yProps::live: Option<accesskit::Live>`
  — new `A11yProps` field, default `None`).
- During Effect, when a `live`-annotated node's `name` or `description`
  signal fires, the dirty-marking observer also pushes the node onto
  an in-frame `live_announcements: SmallVec<[NodeId; 2]>` list. The
  drain emits the AccessKit `Live::Polite`/`Assertive` annotation on
  those nodes in the published `TreeUpdate`.

DR-047 §6 named the deferred-write queue that swallows Paint-phase
dispatches and replays them in the next Effect. Live announcements are
the dual: events emitted during Effect that are observable by the AT
only after Effect completes. Same drain principle, dual direction.

Why end-of-Effect, not start-of-Layout or end-of-Paint:

- **Not start-of-Layout:** Layout reads the dirty set; if drain is in
  Layout, observers that fire during Layout's setup miss this frame's
  drain. Effect already settles the reactive graph; once Effect ends,
  the dirty set is complete.
- **Not end-of-Paint:** Paint is read-only and must not invalidate
  itself. Publishing the tree update in Paint introduces the
  re-entrancy DR-047 banned. Also: AT polling cadence on Windows UIA
  is typically 50–100ms; publishing in Paint risks the AT seeing
  inconsistent state between layout-computed bounds and the published
  tree's bounds if Paint takes longer than expected.
- **End-of-Effect, before Layout:** Layout reads bounds; the published
  tree reads bounds *from the previous frame's Layout output*. The
  one-frame lag on bounds is acceptable (AT reads bounds for
  hit-testing, which is naturally one frame stale anyway because the
  user's pointer is reading screen-space coordinates from before the
  application's next paint).

### 9. WCAG 2.2 AA is the conformance target; named criteria gate Wave 5 dispatch

G10 names the target. WCAG 2.2 AA, with the following criteria as the
gating set every Wave 5 widget must pass:

| Criterion             | Requirement                                                                 | Implementation crate                                     |
| --------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------- |
| 1.4.3 Contrast        | Body text ≥ 4.5:1, large text ≥ 3:1, UI components ≥ 3:1                   | `sigil-style` (theme palette tokens — `on-surface` etc.) |
| 1.4.11 Non-text Contrast | UI component boundary ≥ 3:1 against adjacent colours                     | `sigil-style` + per-widget visual review                 |
| 2.1.1 Keyboard        | All functionality available from keyboard                                   | `sigil-events` + widget `.on_key(...)` discipline        |
| 2.1.2 No Keyboard Trap | Tab leaves any non-modal scope                                             | `sigil-events` (`FocusScope::Modal` is the explicit trap)|
| 2.4.3 Focus Order     | Tab order matches reading order                                             | `sigil-events::FocusManager::build_ring` (Decision 6)    |
| 2.4.7 Focus Visible   | Focus indicator rendered on focused node                                    | `sigil-style` `:focus` state, `interaction.focus_visible`|
| 2.5.5 Target Size (AAA-leaning, AA-from-2.2) | ≥ 24×24 CSS px for pointer; ≥ 16×16 fallback under spacing | per-widget `LayoutStyle` discipline (sizes in widget files) |
| 3.3.1 Error Identification | Errors announce via aria-live                                          | `sigil-a11y` (Decision 8) + widget `aria_live` usage     |
| 4.1.2 Name, Role, Value | Every interactive element has all three                                   | DR-050 §3 compile-time gate                              |
| 4.1.3 Status Messages | Status emits aria-live notification                                         | DR-050 §8 live-region drain                              |

The a11y-reviewer agent (a future seat per the structured Wave 5
dispatch flow) checks every catalogue widget against this gating set
before the widget marks `cargo test` green. Criteria 1.4.x are static
palette checks (theme tokens carry contrast metadata); 2.x is keyboard
nav verified by snapshot; 4.x is the compile-time gate from Decision 3.

### 10. Test infrastructure — frame-driver harness produces the AccessKit tree; `accesskit_consumer::Tree` is the assert helper

The headless test harness lives in `crates/a11y/src/testing.rs`:

```text
fn drive_widget<W: IntoNode>(widget: W) -> accesskit::TreeUpdate
```

Steps internally:

1. Create a fresh `Cx` (no platform adapter; the bridge is a recording
   bridge that captures `TreeUpdate`s into a `Vec`).
2. Build the widget into the `Cx`.
3. Drive one frame: Effect → Layout → Paint (the Paint phase is
   stubbed; we only need the tree, not GPU output) → Idle.
4. Return the captured `TreeUpdate`.

Tests pull the tree into an `accesskit_consumer::Tree` (the official
AccessKit test-side helper crate, workspace dep
`accesskit_consumer = "0.24"` matching the bridge pin) and walk it to
assert. The `assert_a11y_tree!` macro from Decision 7 is the
ergonomic wrapper around this pattern.

The harness also captures the inbound `ActionRequest` queue. Tests
that exercise AT-initiated actions (`fire_action(InvokeButton)`)
inject the request via `A11yBridge::take_action`'s test-side
recording implementation, drive one more frame, and assert the
outcome (e.g. the button's `on_activate` callback ran).

This is the substrate DR-008 promised at "every primitive in the
catalogue has a mandatory a11y test using AccessKit's test harness."
G10 supplies the harness; Wave 5 widgets supply the tests.

## Consequences

- **One new crate (`sigil-a11y` at `crates/a11y/`)** with three
  modules: `mapping.rs` (the projection table from Decision 2),
  `bridge.rs` (the `AccessKitBridge` impl of `A11yBridge` over
  `accesskit::Adapter` plus the recording bridge for tests),
  `snapshot.rs` (the `assert_a11y_tree!` macro + text formatter).
  Module budget ~250 LoC each; hard-split at 350.
- **One new builder method (`NodeBuilder::aria_live`)** and one new
  `A11yProps` field (`live: Option<accesskit::Live>`). Default `None`,
  no behaviour change for any existing widget.
- **One new builder method (`NodeBuilder::focus_scope`)** and one new
  kernel extension (`FocusScopeExt`). `FocusManager` reads the
  extension to constrain ring building.
- **Kernel `FocusHandleNodeExt`** extension type (Decision 5).
  Attached by the `Cx::build` path when the built widget participates
  in entity-focus; consumers do not manage it.
- **One new `RuntimeState` field (`a11y_dirty: AHashSet<NodeId>`).**
  Plus one transient per-frame `live_announcements:
  SmallVec<[NodeId; 2]>` cleared at the end of Effect drain.
- **One new `Cx` debug-assert** firing on attach: "named role
  requires AccessibleName" (Decision 3). Compiled out in release.
- **One new tests subdirectory (`tests/snapshots/a11y/`)** at the
  workspace level; per-widget snapshots populate during Wave 5.
- **`A11yBridge` associated types pin to AccessKit.** `sigil-a11y`'s
  `AccessKitBridge` sets `type Update = accesskit::TreeUpdate;
  type Action = accesskit::ActionRequest; type NodeId =
  sigil_kernel::NodeId;`. The HAL trait stays generic; the in-tree
  impl is concrete.
- **Wave 5 widget catalogue dispatch unlocks.** Every catalogue widget
  brief now references DR-050 §3 (the compile-time gate) and DR-050 §7
  (the snapshot test seam). A widget that does not produce a passing
  `tests/snapshots/a11y/<widget>.txt` cannot mark cargo green.
- **The visual-gate-essential argument extends to a11y.** Pixel diff
  catches rendering regressions; a11y snapshot catches semantic
  regressions; the two together catch the GPUI/Floem
  rendering-correct-but-AT-broken bug class (see
  `feedback_visual_gate_essential`). Wave 5 widget dispatch gets both
  gates as a verification target.
- **a11y-reviewer agent gate (future seat).** Reads catalogue widget
  files + their snapshot output, asserts the WCAG 2.2 AA criteria
  from Decision 9 are honoured. The reviewer is read-only and lands
  as a the author plugin seat alongside the existing visual-quality
  reviewer.
- **No widget code changes are required for G10 itself.** Every widget
  already has `.role(...)` and `.aria_label(...)` (verified). G10
  produces snapshots for the existing widgets as a baseline; Wave 5
  widgets ship with snapshots from day one.
- **Linux `tokio` feature pin remains.** Per DR-008's zbus panic
  workaround, `accesskit` is consumed with the `tokio` feature. G10
  inherits this; `sigil-a11y` declares the feature on its accesskit
  dep.

## Alternatives considered

### Webview a11y delegation (let an embedded webview own the AT surface)

Rejected. DR-040 §AI surface explicitly forbids webviews for the AI
panel; the same reasoning applies to a11y. Delegating to a webview
means three external dependencies (Edge WebView2, WebKit, WebKitGTK)
plus their per-OS lifecycle issues, plus AccessKit-on-the-other-side
of an IPC boundary for the *non-webview* widgets. The complexity
exceeds the implementation effort of the AccessKit bridge by an order
of magnitude.

### One a11y tree per widget (let each widget call `AccessKit::publish` directly)

Rejected. The exact retrofit failure DR-008 named. The tree update
contract requires one atomic publish per frame; widgets cannot
coordinate without a central drain point. Every framework that tried
this (Floem early prototypes, an unnamed GPUI experiment) ended up
with re-entrant invalidations and per-widget bridge bugs.

### Single global `enum SigilRole { … }` instead of `accesskit::Role`

Rejected. AccessKit's `Role` enum is the de-facto cross-platform
vocabulary; mapping a parallel sigil enum to it introduces an
exhaustive-match maintenance burden every AccessKit release, plus the
risk of a sigil role with no AccessKit equivalent (or vice versa).
Kernel already re-exports `accesskit::Role` as `kernel::Role` —
that is the right shape.

### JSON snapshot format

Rejected for the reasons in Decision 7. Indented text is the boring
correct choice; the only reason to prefer JSON would be programmatic
re-tooling (e.g. a snapshot transformer), which is not on the
roadmap.

### Per-signal observer registration in widget code (not in the a11y crate)

Rejected. Every widget that touches a reactive a11y field would have
to wire its own observer, duplicating the dirty-marking logic across
20+ widgets. The single `A11yObserverInstaller` in `sigil-a11y` is
attached at node-build time by the a11y crate's hook into `Cx::build`,
so widgets register a `Signal` and the framework handles the
subscription.

### Always-publish full tree every frame (no dirty set)

Rejected for performance. The full a11y tree for a typical Wave 5
catalogue scene is ~200–1000 nodes; serialising it every frame
adds proportional cost. The dirty-set diff is already what AccessKit
expects (`TreeUpdate::nodes` is a delta). Building a full snapshot
each frame would also defeat the AT-side caching the adapter
performs.

### Live-region drain in `before_frame` hook (start of frame, before Effect)

Rejected. Effect mutates state; running the drain before Effect
captures the previous frame's state. The result is an off-by-one
announcement: the user toggles a checkbox, the screen reader
announces the *previous* state. End-of-Effect drains the freshly
settled state.

### Skipping `tab_index` honoring (DOM order only)

Rejected. Form-field flow is the entire reason `tabindex` exists in
HTML; sigil widgets that build form layouts (text fields, checkboxes,
buttons stacked vertically with a label above each input) need the
explicit override. DOM-only order also fails for visual hierarchies
that don't match reading order (e.g. a "Save" button positioned
top-right but tab-ordered after the form fields).

### Defer WCAG conformance target to a future DR

Rejected. The whole point of locking the substrate now is that Wave 5
widget briefs reference the target. Without a named target, "a11y
testing" is undefined for every catalogue widget; with the target,
the a11y-reviewer agent has criteria to check against.

### Focus stored on `Signal<Option<EntityId>>` (re-evaluating DR-046 §3)

Rejected — same reasoning as DR-046 §3, reaffirmed. Focus is read
once per dispatch and once per frame's a11y publish, not a stream.
A signal-driven focus wakes every observer of focus on every move,
which the AT polling cadence makes pathological.

## Open questions

These are explicitly not resolved in this DR. They land in follow-up
DRs or W4.G10-impl implementation discovery.

1. **Test snapshot format extensibility.** The indented-text format
   covers Role + Name + State; what does a tree with custom
   AccessKit fields (e.g. `Node::set_min_numeric_value` on a slider)
   render as? Provisional: include any AccessKit field whose value is
   not the AccessKit default. Lock at first widget-bench that needs
   a non-default field.

2. **`FocusScope::Popup` click-outside-escapes mechanism.** The
   `Popup` variant traps Tab but lets click-outside escape. The
   click-outside detection needs to interrogate the input layer
   (`sigil-events`) for hit-test results outside the scope root.
   Provisional shape: `FocusManager` listens for `PointerDown` events
   and pops the topmost `Popup` scope when the hit-test target is not
   a descendant of the scope. Lock when the dropdown widget (Wave 5)
   exercises the case.

3. **AccessKit version drift policy.** AccessKit 0.24 is the pin;
   minor-version bumps (0.25, 0.26) typically add fields to `Node`
   without breaking existing usage. Provisional policy: bump on patch
   automatically (cargo update), gate minor bumps on a one-page DR
   addendum recording new fields' effect on `A11yProps`.

4. **High-contrast theme variants.** WCAG 2.2 AA contrast is met by
   the default theme palette; high-contrast variants (Windows
   high-contrast mode, system-respecting dark/light) are out of scope
   for G10. Future DR-051 or a `sigil-style` extension.

5. **Voice control (out of scope, OS-level).** Windows Voice Access,
   macOS Voice Control, and Linux speech-to-text dispatch standard
   AccessKit actions; they should "just work" once the bridge is
   live. Explicitly not a G10 verification target.

6. **a11y dynamic content (live regions beyond `Polite`/`Assertive`).**
   Full ARIA live-region semantics include `role="status"`,
   `role="alert"`, `aria-busy`, `aria-relevant`, etc. G10 covers the
   two most common (`Polite` / `Assertive`); the full matrix is G10.2
   when a widget actually needs the broader vocabulary (e.g. terminal
   widget streaming output).

7. **CI screen-reader smoke tests (NVDA / VoiceOver / Orca).** DR-008
   named these for Phase 9. G10 lays the bridge that makes them
   possible but does not run them on CI yet. Open as a Phase-9
   follow-up; G10's snapshot tests are the substitute until then.

8. **Action-request authorisation.** Some AccessKit actions (e.g.
   `SetValue` on a text input) carry data the AT supplies. Should the
   bridge filter actions on the receiving side (rate-limit, sanitise)
   or trust the OS-level AT? Provisional: trust the OS; the AT is
   already authorised to drive the application. Re-evaluate if any
   real consumer flags it.
